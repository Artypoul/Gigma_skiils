# Behavior pipeline

## v2.0 safety and completeness

- Inventory runs on the pinned offline donor inside the same deny-by-default network sandbox used for live inputs. Fetch/beacon/WebSocket/EventSource/navigation/form/download effects are blocked unless an exact request/action rule permits them; blocked navigation/download intent is compared without executing it.
- Discovery includes actionable semantic controls, registered/inline/property event handlers, every reached state, open shadow roots and same-origin frames. Structural ARIA roles do not create fake actions. Truncation, delegated document/window listeners, closed-shadow or cross-origin interactive boundaries are explicit non-pass evidence.
- Matrices contain applicable sequences, not hover/focus/click invented for every node. Escape/outside-close have an open prerequisite; forms, keyboard focus, touch/pointer drag, scroll and navigation intent are recorded where applicable. A no-op fails only when `expected_transition` is declared.
- Every root sequence starts from the pinned isolated storage state. Candidate replay applies the injective implementation map to the primary selector and every prerequisite/action selector. Original action/runtime errors make the reference non-final; candidate errors, blocked outcomes, before/after semantic/intent/accessibility mismatches and post-state pixel differences fail comparison. A synthetic handler registration is never accepted as an observed transition.
- Original traces are frozen in the atomic reference bundle and never regenerated by the current candidate runner.

1. `behavior_inventory.js` scans the original page for interactive controls.
2. `behavior_matrix_generate.js` converts inventory into reproducible interactions.
3. `behavior_capture_trace.js` records before/after semantic state and screenshots.
4. `behavior_build_state_targets.py` turns original traces into targets.
5. Candidate implements behavior and maps selectors in `behavior_implementation_map.json`.
6. Candidate traces are captured with the same matrix.
7. `behavior_compare_traces.py` fails on missing/extra states, errors, intent, accessibility, semantic or scoped visual mismatches.


## v1.7 note

Behavior covers interactions; liveness covers runtime motion/rendering. Use `h2d-transfer-liveness-motion-webgl.md` from the same reference bundle when the original has animation, canvas, WebGL, video or scroll-linked effects.
