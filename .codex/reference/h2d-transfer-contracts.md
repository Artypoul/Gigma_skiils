# Contracts overview

The package uses one naming system across docs, schemas, templates and scripts. Contract v2.0 makes final evidence current and immutable; the v1.x report contracts below remain the individual gate payloads.

Static scope requires `behavior_validation.json` with `result=static-scope` or `not-tested`.
Interactive scope requires full behavior artifacts. Requiredness comes only from the pinned reference classification in `transfer_contract.json`; neither a CLI guess nor a missing report can downgrade the scope.


## v2.0 immutable/current-evidence contract

`transfer_contract.json` pins:

- the H2D bytes, bundled decoder identity and freshly regenerated decoded/tree artifacts;
- decoded widths plus generated donor breakpoint-boundary and interval probes. Breakpoint provenance is the bundled reachable-state classification (CSS/media queries and runtime `matchMedia`), never a filename/manual list; seed discovery is followed by final-matrix recapture;
- complete browser profiles, including DPR, touch/mobile input, locale, timezone and reduced motion;
- exact candidate include closure, every command executable/file input resolved from its exact current/lifecycle cwd, managed build/start/health/teardown and public toolchain/environment identity. Managed URL mode starts only on an unused loopback origin and serves JSON whose source/candidate digests match the current contract;
- classification, sidecars, verified owner approvals, expected reports and regeneration commands. An approval only verifies against an external trust anchor: Ed25519 keys come from `H2D_OWNER_PUBLIC_KEYS_JSON`, while connector receipts come from `H2D_TRUSTED_OWNER_EVENTS_JSON`; a `verified: true` field inside the contract is never sufficient;
- one `reference_bundle.json` whose visual, generated reachable-state classification and dynamic artifacts share a donor identity computed from the transitive local runnable closure, including resources loaded only in reached interaction states. Dynamic artifacts require the bundled finalizer, exact classification hash, complete required role×matrix coverage and non-empty hashed files. Rendering/GL fingerprints are pinned per browser profile; page font declarations are compared by typography gates, not mixed into the browser/platform identity hash.

`current_evidence.json` is generated only by `run_current_gates.py`. Before commands run, every expected report (including `review.md`) plus prior current/final evidence is moved out of the active paths. The runner verifies that final `source/` copies match the pinned `.h2d` and both decoded artifacts. Matrix completion is generated by the runner from freshly hashed visual, geometry, typography and required behavior/liveness artifacts; each artifact must carry the bundled specialist generator hash, the contract must directly invoke that exact script, and every exact key needs an allowed passing verdict. A copied template, wrapper-authored row, `not-tested`, or `static-scope` never satisfies a required role. `run_all_gates.py --output` independently verifies this evidence, including source-artifact hashes and a fresh candidate closure digest.

The evidence output/cache is narrowly excluded from the candidate digest so generation does not invalidate itself. All real source, config, dependency and build inputs must be explicit includes. A changed include, sidecar, source, decoder, reference artifact or contract makes the old run stale.

Approvals are not self-authenticating JSON. Any accepted deviation, changed-source choice, font substitution, asset decision, equivalence or static fallback needs a verified owner signature or trusted owner-controlled event receipt with exact scope. Locally authored identity/timestamp/hash fields do not pass.


## Mandatory source and final gate

The runner must require `source_manifest.json` plus these files before final pass:

- `source/input.original`
- `source/input.h2d`
- `source/input.sha256`
- `source/h2d_decoded.json`
- `source/h2d_tree_index.json`

A transfer is not done until `python scripts/run_current_gates.py --contract h2d-transfer-output/contract/transfer_contract.json --output h2d-transfer-output` creates both `reports/current_evidence.json` and `reports/validation_run.json` with `result=pass`.


## v1.7 liveness contract

If `liveness_required=true`, the output contract includes `liveness_inventory`, `webgl_capture_report`, `original_animation_trace`, `candidate_animation_trace` and `liveness_validation`. If `liveness_required=false`, `liveness_validation.json` still exists and explains `static-scope` or `not-tested`.


## v1.8 design-system and provenance contract

**Typography is part of the geometry contract.** `h2d_tree_index.json` rows carry `text_style` (CSS camelCase, straight from the donor's computed styles), `rendered_font` (what the donor's browser actually painted with — the only evidence of a fallback) and `box_style` (container constraints). `extract_rect_targets.py` copies all three onto the targets, and `validate_active_viewport.js` compares them:

- text metrics (`fontSize`, `fontWeight`, `lineHeight`, `letterSpacing`, `textAlign`, `textTransform`, `color`) fail the gate;
- `fontFamily` differences are warnings — `font_manifest.json` owns family identity and may legitimately be `font-substituted` when the donor face lacks the candidate's script;
- `box_style` differences fail by default (`--lenient-box-style` temporarily downgrades them to warnings) — a container constraint replaced by a parent offset reaches the same rect, which is exactly the compensation this field exists to catch.

`font_manifest.json` is required with `result` in `{font-exact, font-substituted}`. The final runner cross-checks it against the measurement: a manifest claiming `font-exact` next to measured family mismatches fails as a contradiction, so a stale manifest cannot green-light the very failure the font gate exists to catch.

**Two candidate modes.** Marker mode uses `data-h2d-path`/`data-h2d-viewport` attributes. Integration mode targets a real project page (file or URL) with `--selector-map`, a `{path: selector}` or `{viewport: {path: selector}}` map, so a transfer into an existing application can pass the same gate without polluting production markup.

**Accepted deviations.** `--accepted-deviations` takes owner-approved deltas. Every entry must name the node (`data_h2d_path`/`paths`), the concrete `viewport`/`viewports`, a non-empty explicit `fields` list (`"*"` is rejected) and a substantive `reason`; anything vaguer is a hard error rather than a silent blanket approval. Approved deltas are reported under `accepted_deviations` instead of failing, which is how the content-divergence protocol reaches a green gate honestly: the deviation is recorded, not hidden.

**Asset provenance.** `asset_provenance.json` (generated by `scripts/asset_provenance.py`) is required with `result=pass`. Assets are matched to the donor inventory by content hash. Donor-derived assets need a declared `third_party_brand`; third-party brand content or anything at or above `size_threshold_bytes` (default 1 MB) needs an `owner_decision`. An `unknown` origin fails: bytes that are in neither the inventory nor the decisions file have no proven source.

**Drifted donor.** `diff_summary.result=changed-source` no longer blocks readiness forever, and it is produced by the pipeline rather than by hand: `capture_visual_diff.js --changed-source '<reason>'` requires `--original`, so the verdict always ships with captured evidence and a stated reason. After the owner confirms that the `.h2d` snapshot stays the reference, `run_all_gates.py --accept-changed-source` accepts it and records `changed_source_accepted: true` in `validation_run.json`. Without that flag the state stays honest and non-final.

**Asset arguments.** `asset_provenance.py` fails on any `--assets` argument that matches no file, and on an empty result unless `--allow-empty` is passed: a mistyped glob must never turn a skipped check into a green gate. `owner_decision: "removed"` for a file that is still in the shipped set is likewise an issue, not an approval.

**Browser driver.** All JS gates launch through `scripts/browser.js`, which resolves `playwright` or falls back to `playwright-core` plus an installed Chrome/Edge. `--browser-executable <path>` is parsed inside the launcher, so it works in every bundled gate, and `CHROME_PATH` remains as the environment-level override. A missing driver is an environment blocker, never a gate verdict.


## v1.9 system-transfer contract

**Design system report.** `design_system.json` (generated by `scripts/extract_design_system.py` from the decode) is required with `result=pass`. It names the donor's recurring tokens (colors, type scale, spacing, radii, shadows), the shared per-viewport container widths, the recurring flex/grid layout mechanisms and the repeated subtrees (`components`). The candidate implements tokens as one shared layer and each repeated pattern as one component. Capture artifacts in the snapshot (translation spans, overlay fonts) are excluded from the maps, not transferred. Under the current-evidence contract both `design_system.json` and `component_reuse.json` belong in `expected_reports` and are regenerated by `current_commands`, so a stale report from an earlier donor is quarantined instead of accepted.

**Component reuse is candidate-side.** `component_reuse.json` (generated by `scripts/validate_component_reuse.js`) is required with `result` in `{pass, no-repeated-patterns}`. The agent maps each repeated donor pattern to a candidate selector in `component_map.json` (or excludes it with a reason); the gate then proves reuse on three layers. Source: each entry names its single `definition` file inside the candidate root, the file exists and mentions the selector's identifiers — pasted copies have no single definition to point at. Count: the expected instance count is derived from the donor report (`components[].count`), not from the map author; diverging is legitimate only through `instances_expected` plus a substantive `instances_reason` recording the owner's content decision. Render: each component is checked at its own donor viewport (mobile-only patterns are judged in a mobile DOM state), and all found instances must share one subtree shape and one set of computed tokens. Donor extraction alone proves nothing about reuse — this gate is what rejects N pasted, individually edited copies.

**Grid elasticity.** Track ratios at one width cannot tell an `fr` grid from fixed pixels tuned to match at that width. `validate_active_viewport.js` therefore also compares how each track CHANGES between the measured widths: a donor track that grows with the container while the candidate's stays frozen (or vice versa) is a `grid-elasticity` failure, attributed to the wider viewport of the offending pair. Samples are keyed by the branch-independent canonical path (`alt2:0.5.1` → `0.5.1`), because each responsive branch prefixes the same logical node differently and a raw-path key would leave every sample list at length one.

**Declarative inputs vs reports.** Hand-authored declarations live under `contract/`, never `reports/`: `contract/component_map.json`, `contract/selector_map.json`, `contract/asset_decisions.json`. Reports are generated only; `design_system.json` and `component_reuse.json` carry `generator_sha256`, and the final runner rejects a report whose hash does not match the bundled generator script.

**Styleless decodes.** A valid geometry-only snapshot (no per-node `styles`) yields `design_system.result = "not-tested"` — accepted by the runner, with the limitation named in `issues` and `review.md`; tokens are then derived from the runnable donor reference. `needs-fix` remains the verdict for extractions that should have worked and did not.

**Component inventory is exhaustive.** The display limit applies to token/layout tables only; `components` lists every repeated pattern (hard cap 512 with an explicit truncation issue), each carrying `signature_sha256` alongside the truncated display signature, and the reuse gate matches by hash when present. Container widths require spread across at least two distinct parents, so a card grid's shared width does not masquerade as the page container chain. `--min-component-repeats` is bounded to 2–5 and recorded in the report — a huge threshold would empty the inventory and turn the reuse gate into an automatic `no-repeated-patterns`.

**Reuse gate hardening (v1.9.1).** Self-serve exclusions are limited to known injector tag prefixes (Yandex/Google translate, Grammarly, DeepL and similar); a hyphen alone does not make a tag a capture artifact, because donors legitimately ship Web Components — any donor-authored pattern needs an `approval_ref`. Mapped candidate instances must also match the donor pattern's structural skeleton (root tag, presence of children), so a map cannot point a donor card at an unrelated repeated element with a convenient count.

**Token reuse is candidate-side (v1.9.1).** `token_reuse.json` (generated by `scripts/validate_token_reuse.py`) is required with `result` in `{pass, no-donor-palette}`. Each significant donor color (rgb and hex spellings alike) must live in the candidate's token layer (`--token-file`, or sources named tokens/theme/variables/palette/tailwind.config); more than `--max-scatter` literal occurrences outside that layer fail — a palette hardcoded block by block is the token-level compensation. Together with the contract binding, all three system reports (`design_system`, `component_reuse`, `token_reuse`) are quarantined, regenerated by pinned commands and provenance-checked.

**Layout mechanism is gated.** `box_style` on indexed nodes now includes `display`, `flexDirection`, `flexWrap`, `justifyContent`, `alignItems` and `gridTemplateColumns` (flex/grid containers are always indexed). `validate_active_viewport.js` compares them like the other container constraints — `gridTemplateColumns` by track count, since computed styles resolve tracks to used pixels — so identical rects laid out by absolute offsets instead of the donor's flex/grid chain fail the gate instead of shipping a page that measures right and resizes wrong.
